# DeepSeek через совместимый шлюз

В `.env` задаются `AI_PROVIDER=deepseek`, `AI_MODEL=deepseek-v4-flash`,
`AI_BASE_URL=https://api.relaymodels.com/v1`, `AI_TIMEOUT=30s` и секретный
`AI_API_KEY`. Ключ не добавлять в документацию, Git или команды терминала.
`.env` исключён из Git и Docker build context; рекомендуемые права — `600`.

Провайдер использует `/chat/completions`, сообщения `system` и `user`,
лимит ответа 180 токенов и `thinking: {type: disabled}`. Редиректы запрещены.
OpenAI и Codex продолжают использовать прежний Responses API.
Формат Chat Completions сверён через OpenAI Docs:
https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create

Шлюз получает инструкции и включённые ботом фрагменты переписки. Совместимость
API не гарантирует политику хранения данных или подлинность модели посредника.
Имя модели в ответе сохраняется в учёте вместе с входными/выходными токенами.
Коэффициенты списания баланса продавца бот не предполагает и не вычисляет.

Проверка без Telegram и изменений БД (расходует реальный баланс):

```sh
docker compose exec bot /app/bot aicheck
```

Команда показывает текст, модель, время и токены. Пустые, оборванные ответы,
ошибки и таймауты не выдаются за ответ кота. Для прямого вопроса остаётся
честное сообщение о недоступности ИИ; шаблоны игровых событий сохранены.

Для возврата на локальный мост: `AI_PROVIDER=codex`, `AI_MODEL=gpt-5.6-luna`,
`AI_TIMEOUT=30s` и пересоздание только контейнера бота. Мост и его сокет
не удаляются при подключении DeepSeek. Расписание сообщений не меняется.

## Перед обновлением

Сохраняйте резервную копию за пределами `/tmp`, с доступом только владельцу.
Храните дополнительную копию вне сервера. Не включайте дампы в Git или архив кода.

```bash
mkdir -p backups
COMPOSE_FILE=docker-compose.dev.yml scripts/backup_db.sh "backups/$(date -u +%Y%m%dT%H%M%SZ).dump"
```

Скрипт не перезаписывает существующий архив и проверяет его формат.
Для production используйте `COMPOSE_FILE=docker-compose.yml`.
Ежедневный запуск устанавливает `./scripts/setup_backup.sh docker-compose.dev.yml`.
Для production передайте `docker-compose.yml`. Требуются Linux с пользовательским
systemd, Python 3, flock и доступ пользователя к Docker. Скрипт устанавливает
`catforge-backup.service` и `.timer` в пользовательский systemd, включает linger
(выполнение без открытой сессии) и сразу создаёт первый архив. Запуск — ежедневно
в 04:00 МСК с задержкой до 5 минут; пропущенный запуск догоняется после включения
машины. Ошибки повторяются через 15 минут; один запуск ограничен 15 минутами.

Архивы `backups/daily-*.dump` публикуются после проверки формата, с правами 600.
Параллельные запуски защищены flock. Автоматическое удаление архивов не настроено.

```bash
systemctl --user list-timers catforge-backup.timer
journalctl --user -u catforge-backup.service -n 20
systemctl --user start catforge-backup.service
```

Для дополнительной копии на уже подключённое внешнее хранилище добавьте
`BACKUP_OFFSITE_DIR=/путь/к/точке/монтирования` в `~/.config/catforge-backup.env`.
Храните этот файл с правами 600. Каталог должен быть существующей точкой монтирования;
при её отсутствии сервис завершится ошибкой, сохранив локальный архив. Копия
проверяется побайтово и публикуется атомарно. Удалённый адрес и учётные данные
скрипт не выбирает и ничего наружу не отправляет без настройки. Сам таймер
не подтверждает, что копия находится на другой машине.

## Обновление

Go и C++ выкладываются вместе. Бот применяет миграции при старте.
Для существующего локального polling-стека:

```bash
docker compose -f docker-compose.dev.yml build bot game-engine
docker compose -f docker-compose.dev.yml up -d
docker compose -f docker-compose.dev.yml ps
curl --fail http://127.0.0.1:8080/readyz
```

В dev порт PostgreSQL опубликован только на `127.0.0.1`; контейнер бота продолжает
подключаться к `postgres:5432` во внутренней сети Docker.

Production использует `docker-compose.yml`, домен, HTTPS-сертификаты и
`TELEGRAM_WEBHOOK_SECRET`. Не запускайте второй экземпляр с тем же токеном.

`/healthz` проверяет жизнь HTTP-процесса; `/readyz` — подключение к PostgreSQL
и stateless RPC движка с текущей версией правил. Ошибки зависимостей дают 503
без внутренних деталей. Это не проверка доступности Telegram или AI.
Compose проверяет `/readyz` каждые 30 секунд. `restart: unless-stopped`
перезапускает завершившиеся контейнеры; статус unhealthy сам по себе Docker
не перезапускает. Для беты нужно наблюдать за состоянием и логами сервисов.

## Проверка восстановления

Восстанавливайте сначала в **новую пустую тестовую БД**, без подключённого бота:

```bash
createdb -h 127.0.0.1 -p 55439 catforge_restore_check
pg_restore -h 127.0.0.1 -p 55439 -d catforge_restore_check \
  --no-owner --no-acl --exit-on-error backups/ИМЯ.dump
psql -h 127.0.0.1 -p 55439 -d catforge_restore_check \
  -c 'SELECT max(version_id) FROM goose_db_version WHERE is_applied'
```

При аварии остановите бот, восстановите архив в новую БД и переключите
`DATABASE_URL` на неё. Используйте совместимые версии Go и C++.
Не запускайте старый бинарник поверх новой схемы без проверки совместимости.
Не удаляйте текущий volume и не применяйте `docker compose down -v`.

## Ручная проверка перед приглашением чатов

Ниже полный сценарий с двумя аккаунтами; частичные подтверждения указаны в таблице выше:

- [ ] Создать двух котов в личке, проверить профиль, имя и сохранение после перезапуска.
- [ ] Добавить бота в группу; настройки и удаление доступны только владельцу в личке.
- [ ] Тренировка расходует энергию; повторное быстрое нажатие не дублирует награду.
- [ ] На Lv2 появляется первый предмет, на Lv3 открывается арена.
- [ ] Два кота проходят очередь арены; повторный бой ограничен на 24 часа.
- [ ] Два участника выбирают роли события; финал и награды приходят один раз.
- [ ] `/askcat`, `/cat` и обычный reply коту работают; при отказе AI есть fallback.
- [ ] Администратор проверяет `/quiet`, autospeak, banter и запрет драк;
      обычный участник не может менять настройки Двора.
- [ ] `/week` показывает результаты текущего Двора.

После этого пригласить несколько чатов на неделю и наблюдать: тренировки,
участие в событиях, возвращение на арену, ответы котам и отключения AI.
AI-сигналы доступны в `analytics_ai_life_daily`.

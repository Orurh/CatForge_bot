# Поддержка CatForge через Telegram Stars

Разовая добровольная поддержка: быстрые суммы 50 / 100 / 250 / 500 / 1000 / 2500 XTR или своя целая сумма от 1 ⭐. Игровых преимуществ, подписки и публичной отметки нет. C++ и GameEventFanout не участвуют.

## Интерфейс и включение

`/support` и кнопка в личном профиле → сумма → полный текст условий и выбранная сумма → явное «Согласен с условиями» → Telegram invoice. Своя сумма вводится ответом на запрос бота (15 минут, отмена `/skip`) или командой `/support 150`. Обычный текст и ответы на другие сообщения не запускают оплату. `/terms` и `/paysupport` доступны отдельно. Версия принятого текста сохраняется в support_invoices. Текущая версия — `2026-09-08-v2`; кнопки старых условий показывают новые условия для повторного согласия. Меню показывает только `/support`.

`PAYMENT_SUPPORT_CONTACT` задаёт реальный @username или email ответственного за оплату и возвраты. Пустое значение выключает новые счета и pre-checkout, но сохраняет приём уже совершённых оплат/возвратов и доставку благодарностей. Не подставлять выдуманный контакт. Условия описывают разовую поддержку, отсутствие преимуществ, бету, контакт для возврата и хранение платёжных данных.

В sendInvoice: currency XTR, provider_token пустой, одна цена без умножения на 100, непустой start_parameter. Пересланный счёт ведёт в бота; даже при повторном использовании payload проверяется владелец. Go и БД принимают положительные целые суммы, без ограничения набором кнопок. Технический предел ledger — 2 147 483 647 (PostgreSQL INTEGER); это не обещание доступности такой суммы в Telegram. Telegram может отклонить сумму по собственным ограничениям. Миграция `202609080010_support_custom_amount.sql` расширяет CHECK существующих счетов и сохраняет их данные. Старую миграцию не редактировать; откат при наличии нестандартных сумм откажет, не удаляя записи.

## Хранение и доставка

Миграция `202609070010_support_payments.sql`:

- `support_invoices`: пользователь, случайный payload, сумма, продукт, версия условий, срок 24 часа, ключ callback и pre_checkout_query_id.
- `payments`: фактическая квитанция, уникальный telegram_payment_charge_id, сумма/валюта, paid/refunded, время оплаты/возврата, признак ручной проверки, запрос возврата и состояние доставки благодарности.

Pre-checkout проверяет наличие счёта, пользователя, валюту, сумму и срок. БД ограничена двумя секундами, ответ API тремя. В polling уже полученные pre-checkout имеют приоритет перед медленными игровыми обработчиками; истёкший запрос не блокирует последующие платежи. Повтор того же query идемпотентен. Другой query к уже зарезервированному счёту отклоняется: после отмены/таймаута нужно открыть новый счёт через `/support`.

Оплату фиксирует только successful_payment. Финансовые updates обходят ранний `telegram_updates.Claim`. При ошибке БД webhook возвращает 503, polling не подтверждает получение; повтор попадёт в ledger. Транзакция сохраняет квитанцию и статус вместе. Повтор charge ID не создаёт второй платёж. Неизвестная/несовпадающая квитанция остаётся с review_reason и вызывает предупреждение. Refund, пришедший до success, не отменяется поздним success.

Благодарность отправляет worker каждые 5 секунд. Он забирает запись с lease 2 минуты, отправляет и отмечает доставку. Сбой отправки или перезапуск оставляет повторную попытку. Это at-least-once доставка: если Telegram принял текст, а подтверждение в БД не сохранилось, благодарность может повториться. Платёж при этом один. Никаких игровых наград worker не выдаёт.

Telegram хранит pending updates ограниченное время; ledger не заменяет сверку истории Stars после долгого простоя. Общие игровые события остаются best effort — финансовый поток от них независим.

## Возвраты оператором

Нет публичной команды возврата и произвольного ввода charge ID. Оператор сначала находит запись по обращению пользователя в payments. Не публиковать квитанции и Telegram ID в группах.

```bash
# DATABASE_URL и TELEGRAM_TOKEN уже установлены в окружении оператора.
go run ./cmd/payment-refund -payment-id 123
# Только после проверки обращения:
go run ./cmd/payment-refund -payment-id 123 -execute
# Если ответ API потерян или БД не смогла подтвердить результат:
go run ./cmd/payment-refund -payment-id 123 -reconcile
```

В рабочем Compose вместо `go run ./cmd/payment-refund` доступен уже собранный операторский инструмент:

```bash
docker compose -f docker-compose.dev.yml -f docker-compose.monitoring.yml exec -T bot /app/payment-refund -payment-id 123
```

Ключи `-execute` и `-reconcile` те же; без них инструмент только читает запись.

До вызова refundStarPayment сохраняется refund_requested_at. Повторная команда не отправляет второй запрос, пока судьба первого не выяснена. `-reconcile` ищет исходящий возврат с тем же charge ID и получателем в getStarTransactions, затем отмечает refunded. Уведомление refunded_payment также обновляет ledger. Статус refunded идемпотентен. Если запрос заведомо не дошёл до Telegram, оператор после сверки может очистить refund_requested_at и повторить; делать это вслепую при timeout нельзя. Поиск истории ограничен 10 000 транзакций и временем запроса; для более старых записей нужна отдельная сверка.

Перед релизом сохранять backup. Удаление кота не удаляет invoices/payments; миграцию Down не выполнять на рабочем ledger.

## Мониторинг и проверка

Grafana показывает записи на проверку, неподтверждённые возвраты и возраст неотправленной благодарности. Alertmanager сигнализирует локально; внешних уведомлений нет. Метрики не содержат пользовательских идентификаторов.

Автоматические проверки используют подставной Telegram HTTP и отдельную PostgreSQL: повторные и конкурентные квитанции, чужой пользователь, неверные валюта/сумма/payload, истёкший счёт, DB retry, возвраты до/после success, lease/retry благодарности и контракт sendInvoice/pre-checkout. Интеграция не списывает Stars.

Полный end-to-end платёж/возврат в Telegram проверяется владельцем отдельно, сначала в тестовой среде Telegram. Автоматические тесты не доказывают доступность живых платежей у конкретного бота/аккаунта.

Официальные источники: [Telegram Stars flow и требования к terms/support](https://core.telegram.org/bots/payments-stars), [sendInvoice](https://core.telegram.org/bots/api#sendinvoice), [pre-checkout deadline](https://core.telegram.org/bots/api#answerprecheckoutquery), [refundStarPayment](https://core.telegram.org/bots/api#refundstarpayment), [StarTransaction](https://core.telegram.org/bots/api#startransaction).

# Характеры котов

Новые коты равновероятно получают один из шести характеров:

| Trait | Название | Мотив |
| --- | --- | --- |
| `lazy` | лентяй | Бережёт силы, избегает лишней работы. |
| `bully` | борзый | Подкалывает ради реакции и перепалки. |
| `veteran` | бывалый | Спокойный дворовый опыт, простая речь без философии и пафоса. |
| `cunning` | хитрый | Выкручивается и извлекает выгоду, прикидываясь невинным. |
| `arrogant` | наглый | Требует обслуживания как должного, присваивает чужое. |
| `angry` | злой | Искренне раздражён и недоверчив, огрызается без игры на публику. |

Названия используются в профиле и списке котов. AI получает описание характера
и отдельное правило различать борзого, наглого и злого. Резервные реплики без AI
обновлены для знакомства, ответов, продолжения разговора, ухода спать,
отношений, тренировок и успешных событий Двора. На фразу «Я тебе корм купил»
предусмотрены шесть характерных ответов из спецификации.

## Уже созданные коты

Миграция `202609190010_cat_traits_v2.sql` применяется при запуске новой версии:

| Старое значение | Новое |
| --- | --- |
| `lazy` | `lazy` |
| `bully` | `bully` |
| `philosopher` | `veteran` |
| `neat` | `cunning` |
| `sleepy`, чётный ID | `arrogant` |
| `sleepy`, нечётный ID | `angry` |

Уже допустимые новые значения сохраняются. Неизвестные значения распределяются
по шести характерам по ID. Это постоянное сопоставление, без нового случайного
выбора при рестарте.

`cats.trait` и `cat_personality.trait` синхронизируются; стиль речи заменяется
на новый стандартный. Отсутствующие записи личности создаются. Настройки юмора
и автоматической речи существующих записей сохраняются, как и игровой прогресс.
`state_version` увеличивается один раз для защиты от сохранения устаревшего состояния.
Триггер создания личности обновлён; ограничения БД запрещают старые значения.
Старые миграции и исторические события не переписываются.

Рабочую миграцию выполнять через обычный деплой: остановка старого бота,
предмиграционный дамп, запуск нового. `Down` намеренно запрещён: обратное
преобразование неоднозначно. При необходимости возврата восстанавливать дамп
в отдельную БД согласно [инструкции деплоя](DEPLOYMENT.md).

# CatForge — смена фотографии кота (проект реализации)

> Статус: **в разработке в Draft PR**. Реализация и тесты пока проверяются; не считать функцию готовой к релизу.
> Изменения не должны попадать в production до реализации, тестов, проверки платежей и отдельного решения о выкладке.

## Цель

Игрок может заменить стандартную картинку своего кота фотографией, присланной в личном чате Telegram. **Первая успешно одобренная смена бесплатна для Telegram-пользователя**; отклонённая фотография бесплатную смену не расходует. Последующие изменения предполагается оплачивать Telegram Stars по согласованному тарифу.

Для первой итерации — **ручное согласование владельцем бота**, не LLM. Существующий AI gateway CatForge используется для текста и не должен считаться готовым сервисом безопасной проверки изображений.

## Пользовательский путь

1. Игрок открывает личный `/profile` и нажимает `📷 Сменить фото` (или `/photo`). В группах функция недоступна.
2. Бот объясняет ограничения и ждёт именно `message.photo` после этого запроса. Фото вне режима ожидания не изменяет аватар.
3. До отправки заявки проверяются: существует ли кот, владеет ли пользователь котом, нет ли другой нерассмотренной заявки. Предпочтительно проверять тип и размеры изображения, не загружая произвольные документы.
4. Бот сохраняет заявку со статусом `pending` **в PostgreSQL** и пересылает владельцу превью через Telegram `sendPhoto` по `file_id`, с кнопками `Одобрить` / `Отклонить`. Пользователь видит `На проверке`.
5. Callback обрабатывается **только если `callback_query.from.id == CAT_PHOTO_REVIEWER_TELEGRAM_ID`** и заявка всё ещё актуальна. Пересылка сообщения или подмена callback data не должна позволять одобрять чужие заявки.
6. При одобрении бесплатной смены транзакция атомарно фиксирует новое изображение и расход бесплатного права. Пользователь получает сообщение. При отклонении аватар и квота не меняются.
7. Картинка профиля отображается по сохранённому Telegram `file_id` через `sendPhoto` / `editMessageMedia`; существующая PNG по породе — fallback. Не нужен новый публичный HTTP-endpoint или хранилище пользовательских изображений.

## Хранение и инварианты

- `photo_requests`: `id`, `user_id`, `cat_id`, `telegram_file_id`, `status` (`pending`, `approved`, `rejected`, в платной фазе `awaiting_payment` и `applied`), `created_at`, `reviewed_at`, `reviewer_id`. Не более одной активной заявки на пользователя.
- Отдельное состояние **по user_id**, а не по cat_id: удаление/пересоздание кота не сбрасывает бесплатную смену. Текущий аватар привязан к конкретному `cat_id`, чтобы старое фото не переходило к новому коту.
- Решение модератора должно быть идемпотентным, защищённым PostgreSQL-транзакцией от повторных/параллельных callbacks и повторной доставки Telegram updates.
- Проверить, что `cat_id` всё ещё принадлежит тому же пользователю; после удаления или замены кота заявка должна перестать быть применимой.
- Ошибка отправки администратору не должна терять заявку без возможности повторной доставки. Нужен механизм повторного уведомления/список ожидающих заявок.
- Администратор видит исходную фотографию и минимальные сведения о заявке. Нельзя выводить токены бота или ключи сторонних провайдеров в логи.
- Запрос на удаление кота и удаление пользовательских данных должны учитывать новые записи; отклонённые фото и устаревшие `file_id` не следует хранить бессрочно.

## Платные повторные смены (следующий отдельный этап)

Не переиспользовать `support_invoices` как покупку: текущий ledger и `product_id=catforge_support` предназначены для добровольной поддержки без игровых преимуществ.

- После первой бесплатной смены сначала провести модерацию; **после одобрения** отправить одноразовый счёт за конкретную заявку в Telegram Stars (`currency=XTR`).
- Фиксировать отдельно `photo_change` как product, `invoice_payload`, оплачивающего `telegram_id`, сумму, уникальный `telegram_payment_charge_id`, состояние заявки и историю возвратов.
- Проверять pre-checkout с таймаутом Telegram; **активировать фото только после подтверждённого `successful_payment` и фиксации квитанции**. Не начислять право по нажатию кнопки «Оплатить» или успешному pre-checkout.
- Receipt / refund должны быть идемпотентными; при платёжной ошибке заявка не должна молча исчезать. При удалённом коте после оплаты — безопасное урегулирование или возврат.
- Цена фиксирована для этой версии: **10 ⭐** за одобренную повторную смену; сумму валидирует отдельный ledger.
- `/paysupport` и существующий процесс возвратов учитывать отдельно для нового product.

## Безопасная выкладка

1. Реализация — отдельный PR, **без мержа в main во время разработки**.
2. Новые таблицы — только аддитивная миграция; уже опубликованная схема платежей, прогресс котов и `state_version` не должны измениться.
3. Фича по умолчанию **выключена**, пока не заданы `CAT_PHOTO_REVIEW_ENABLED=true` и `CAT_PHOTO_REVIEWER_TELEGRAM_ID`. При выключенном флаге работа старых экранов неизменна.
4. Написать тесты доступа (только владелец/приватный чат), квот, повторной обработки callbacks, удаления кота, отказа модератора, Telegram API failure/retry и одновременных заявок. В платной фазе — pre-checkout и дубли payment receipt/refund.
5. На PR дождаться успешного CI (Go race, C++ CTest, интеграционные тесты PostgreSQL/Compose), вручную протестировать на **отдельном dev-боте и тестовой БД**. Не запускать dev-бот с тем же Telegram token, что у production.
6. Проверить сохранение существующих Docker Compose project name, volumes, timers и CI `publish`/deploy. Мерж в `main` автоматически выпускает образы, а серверный таймер автоматически подхватывает успешный выпуск; включение флага — отдельное действие после проверки rollback.
7. После мержа в выключенном состоянии: проверить readiness, базовые команды, статус миграций, logs, затем включать конфигурацию только после подтверждения стоимости и Telegram ID модератора.

## Порядок реализации

- **V1:** ручная модерация и однократная бесплатная смена, фича выключена по умолчанию.
- **V2:** платные повторные смены через новый Stars product/ledger с отдельным receipt flow.
- **V3 (опционально):** автоматическая проверка изображения мультимодальной моделью до ручного согласования. Нынешний текстовый AI gateway не умеет автоматически проверять фотографии; модельный ответ не заменяет проверку модератора.

### Конфигурация и оставшиеся проверки

- `CAT_PHOTO_REVIEW_ENABLED=false` — значение по умолчанию, функция скрыта и не обрабатывает загрузки.
- `CAT_PHOTO_REVIEWER_TELEGRAM_ID` — ID модератора, хранится в окружении сервера, не в исходниках.
- После проверки CI: протестировать отдельно получение фотографии и модерацию на dev-боте; затем подтвердить реальные платежи и возвраты Stars.

### Открытые решения

- Стоимость каждой последующей одобренной смены: **10 ⭐**.
- Telegram `user_id` единственного модератора: задаётся **только в server-side .env**, не в коммите и не через публичный username.
- Политика для подозрительных изображений: ручное отклонение; при необходимости отдельная кнопка блокировки дальнейших заявок.
